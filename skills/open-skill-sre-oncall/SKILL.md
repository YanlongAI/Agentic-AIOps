# SRE：值班交接

## 何时使用

- 用户要 **值班交接**、**交接班**、交班、接班
- 搜索 **值班**、**on-call**、**oncall**、未关闭告警、下一班要注意什么
- 班次结束，需要把进行中的故障和待执行变更交出去
- 接班人要在动手前先看清现在什么不能动

**不适用**：正在进行的 P0 止损（先走故障应急，交接只记录谁在指挥）；把告警批量关掉冒充交接完成。

## 执行规则

1. 先 `read_skill` 阅读本文档，再查当前告警、工单、值班排班和进行中的根因分析。
2. 交接是只读汇总。静默告警、执行变更、关闭工单仍需确认。
3. 每一条未关闭事项都要写清：现象、负责人、下一步、最晚跟进时间。
4. 不交接「看着正常」这种没有对象的结论。

## 推荐流程

1. **未恢复告警**：按级别列出仍打开的告警。噪声类指向告警降噪结论；真实故障指向应急或根因分析。
2. **进行中的故障**：级别、指挥是谁、已经做的止损、用户影响、下一动作时间。
3. **待执行变更**：窗口、对象、回滚方式、是否受错误预算门禁限制。预算紧张的服务标明「不建议本班发布」。
4. **需要盯的 SLO**：哪些服务在烧错误预算，阈值和查看位置。
5. **已知绕行**：临时静默、降级开关、手工扩容，写明到期时间和谁来收回。
6. **交给下一班的第一件事**：只留一条最高优先级，避免清单长到没人看。

## 输出要求

- 交接时间、交班人、接班人（未知就留空）
- 未关闭告警、进行中故障、待执行变更、临时绕行
- 下一班第一件事
- 明确本班没有擅自关闭告警或执行变更
