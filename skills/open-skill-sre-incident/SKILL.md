# SRE：故障应急响应

## 何时使用

- 用户要 **故障应急**、**事故响应**、**incident**、先止血
- 搜索 **止损**、**MTTR**、**SEV**、**P0**、严重级别、应急指挥
- 真实故障已经确认，告警降噪不够用
- 需要同步影响面、当前负责人、下一步

**不适用**：5～15 分钟内的重复刷屏且尚未确认故障（走告警风暴降噪）；故障已经恢复、只写复盘（走无责复盘）。

## 执行规则

1. 先 `read_skill` 阅读本文档，再查告警、根因分析和近期变更。
2. 先止损、再定位。没有确认影响面之前，不建议重启、回滚、切流。
3. 重启、回滚、扩容、改配置、关告警必须先给出方案，用户确认后再执行，并进工单。
4. 过程中持续追加时间线，不覆盖已有记录。

## 严重级别

| 级别 | 含义 | 动作 |
|------|------|------|
| SEV-1 / P0 | 核心旅程不可用，或大面积错误 | 立即止损，指定一人指挥，同步业务 |
| SEV-2 / P1 | 明显变慢、部分失败，有绕行 | 限时止损，暂停非必要变更 |
| SEV-3 / P2 | 局部、有告警但用户影响有限 | 纳入值班跟踪，避免直接当 P0 扩容 |

级别拿不准时，按更高一级处理，确认后再降级。

## 推荐流程

1. **开场 5 分钟**：现象、开始时间、影响范围、谁指挥、谁记录。指挥只留一个。
2. **止损优先**（确认后才执行）：回滚最近变更、切流、降级非核心、扩容已确认的瓶颈。同时记下做了什么。
3. **核对四件事**：黄金信号、最近发布/变更、依赖是否一起红、告警是不是风暴。
4. **根因先记假设**：用 AI 根因分析做候选，不在应急群里下最终结论。
5. **恢复标准**：用户旅程恢复，SLI 回到 SLO 附近，错误预算不再快速燃烧。然后宣布恢复，把时间线交给复盘。
6. **沟通**：每 15 分钟一条现状（现象、影响、正在做什么、下次更新时间）。没有进展也要更新。

## 输出要求

- 级别、指挥、影响面、开始时间
- 时间线：发现、止损动作、生效时间
- 已做 / 待确认 / 禁止现在做
- 恢复后指出：转无责复盘，并带上告警和工单编号
