# SRE：无责复盘（postmortem）

## 何时使用

- 故障已恢复，用户要 **复盘**、**无责复盘**、**postmortem**、故障回顾
- 搜索 **行动项**、**改进措施**、**根因**、为什么没提前发现
- 同一种告警重复出现，需要把这次结论固化成检查项
- 应急时间线已经有了，需要收成一份可以归档的记录

**不适用**：故障仍在持续（先走故障应急）；只为了认定责任人。

## 执行规则

1. 先 `read_skill` 阅读本文档，再读告警、根因分析、变更记录和应急时间线。
2. 写系统和流程怎么让故障发生、怎么让它变久，不写「某人失误」。
3. 行动项必须有负责人和期望完成时间，并落到工单；没有负责人的不叫行动项。
4. 证据不足的结论标成假设，不写成已证实根因。

## 推荐流程

1. **范围**：开始、发现、止损、恢复的时间；影响的用户旅程和 SLO 消耗了多少错误预算。
2. **时间线**：按时间排列检测、告警、人工操作、变更、外部依赖。缺记录就留空，不补故事。
3. **触发与放大**：
   - 触发因素：哪次变更、流量、依赖或数据导致偏离
   - 放大因素：缺告警、告警被淹没、回滚慢、权限不够、没有降级
4. **哪里做得好**：哪些检测和止损真的缩短了 MTTR，避免复盘只剩批评。
5. **行动项**（每条都要能验收）：
   - 检测：补 SLI 或燃烧率告警
   - 缓解：预置回滚、降级开关
   - 预防：变更门禁、容量、测试
6. **归档**：关联告警、根因分析、工单编号。重复故障要指向上一次复盘，说明上次行动项有没有做完。

## 输出要求

- 标题、级别、影响、持续时长、错误预算消耗
- 时间线与已证实 / 待证实结论
- 行动项表：事项、负责人、截止日期、对应工单
- 声明这是无责复盘，不包含对个人的定性
